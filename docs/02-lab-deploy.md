# Тестовый стенд: мастер + одна площадка

Пошаговый деплой на двух серверах. Цель — проверить репликацию, межузловую
маршрутизацию, failover регистрации и автопровижининг **до** того, как
тиражировать схему на реальные площадки.

Всё используемое бесплатно: MariaDB Community + Galera, Asterisk/FreePBX
community, собственный сервер провижининга на nginx+PHP.

## Что получится

```
              ┌────────────────────────────────┐
              │   Galera: общая база на 2 узла  │
              │   ps_endpoints / ps_contacts    │
              └────────┬──────────────┬─────────┘
                       │              │
        ┌──────────────┴───┐      ┌───┴──────────────┐
        │  master          │◄────►│  site-1          │
        │  FreePBX + GUI   │ транк│  Asterisk        │
        │  провижининг     │ node │  headless        │
        └──────┬───────────┘      └──────┬───────────┘
               │ backup                  │ primary
               └───────────┬─────────────┘
                     ┌─────┴─────┐
                     │  телефон   │
                     └───────────┘
```

## 1. Требования

| Параметр | master | site-1 |
|---|---|---|
| ОС | Debian 12 (bookworm) | Debian 12 (bookworm) |
| CPU / RAM | 2 vCPU / 4 GB | 2 vCPU / 2 GB |
| Диск | 20 GB | 20 GB |
| IP | статический | статический |

Порты между узлами: 3306, 4444, 4567, 4568 (Galera), 5060/udp и
10000–20000/udp (SIP и RTP).

> **Про Debian 12.** Инсталлятор FreePBX 17 рассчитан на bookworm. На
> Debian 11 он не отработает, а сток Debian 11 даёт Asterisk 16 —
> несовместимый по realtime-схеме с тем, что встанет на мастере. Берите
> одинаковый Debian 12 на оба сервера.

> **Про кворум на двух узлах.** Кластер из двух узлов при обрыве связи между
> ними встаёт целиком: обе стороны считают себя в меньшинстве. Для теста это
> терпимо (поднимается вручную), но если хотите честный автоматический
> failover уже на стенде — добавьте арбитра на **третий** хост, шаг 6.

## 2. Подготовка

На обоих серверах:

```bash
apt update && apt -y install git
git clone https://github.com/IIPOCTO4EJIOBEK/Asterisk-claster.git /opt/asterisk-cluster
cd /opt/asterisk-cluster

# Проверка готовности сервера — ничего не меняет, только диагностирует
./scripts/preflight.sh --node-ip=10.10.10.11 --peers=10.10.10.11,10.10.10.12
```

Preflight проверит версию ОС, ресурсы, синхронизацию времени, занятость
портов и — главное — задержку до второго узла. RTT выше 50 мс для синхронной
репликации не годится.

Исправьте всё, что помечено `FAIL`, и повторите.

## 3. Мастер

```bash
./scripts/install-master.sh \
  --node-name=master \
  --node-ip=10.10.10.11 \
  --peers=10.10.10.11,10.10.10.12 \
  --cluster-name=asterisk_lab \
  --admin-cidr=10.10.10.0/24 \
  --phone-cidr=10.10.10.0/24
```

Скрипт последовательно:

1. Готовит ОС и открывает firewall — **SSH первым правилом**, до `ufw enable`.
2. Ставит FreePBX 17 + Asterisk 21 официальным инсталлятором Sangoma
   (20–40 минут).
3. Конвертирует MyISAM-таблицы FreePBX в InnoDB — Galera реплицирует только
   InnoDB, иначе узлы молча разъедутся по данным.
4. Переводит MariaDB в режим Galera и делает bootstrap.
5. Настраивает realtime и кластерный хук диалплана.
6. Разворачивает сервер провижининга.
7. Включает health-check по таймеру.

В конце скрипт напечатает сгенерированные пароли — **сохраните их**, они
понадобятся на следующем шаге и больше нигде не показываются (лежат в
`/etc/asterisk-cluster/cluster.env`, права 0600).

### Порядок «FreePBX, потом Galera» — не случайность

Инсталлятор FreePBX разворачивает и настраивает собственную MariaDB. Если
сначала собрать кластер, а потом запустить инсталлятор, он перепишет
конфигурацию БД и уронит репликацию. Поэтому сначала FreePBX со своей
локальной базой, затем эта база переводится в кластерный режим.

## 4. Площадка

На втором сервере, подставив пароли с предыдущего шага:

```bash
./scripts/clone-node.sh \
  --node-name=site-1 \
  --node-ip=10.10.10.12 \
  --master-ip=10.10.10.11 \
  --master-node-name=master \
  --peers=10.10.10.11,10.10.10.12 \
  --cluster-name=asterisk_lab \
  --asterisk-major=21 \
  --sst-pass='<SST_PASS с мастера>' \
  --rt-pass='<RT_PASS с мастера>'
```

Скрипт присоединит узел к Galera (SST скопирует всю базу), поставит Asterisk
**той же мажорной версии**, что на мастере, и настроит realtime.

`--asterisk-major=21` — не формальность: при несовпадении версий скрипт
откажется продолжать, потому что набор колонок в `ps_*` между мажорными
версиями разный.

## 5. Межузловые транки

На **обоих** узлах с одной и той же картой:

```bash
./scripts/make-node-trunks.sh --peers-map=master=10.10.10.11,site-1=10.10.10.12
```

Проверка:

```bash
asterisk -rx "pjsip show aors" | grep node-
asterisk -rx "pjsip show contacts" | grep node-      # должно быть Avail
```

## 6. Арбитр (по желанию, но лучше сделать)

На **третьем** хосте — подойдёт любая мелкая VM или контейнер:

```bash
./scripts/install-garbd.sh \
  --cluster-name=asterisk_lab \
  --nodes=10.10.10.11:4567,10.10.10.12:4567
```

После этого `wsrep_cluster_size` станет 3, и обрыв связи между узлами
перестанет останавливать кластер.

## 7. Тестовые номера

В FreePBX GUI (`http://10.10.10.11`) заведите 2–3 добавочных
(Applications → Extensions → PJSIP), нажмите **Apply Config**.

Затем на мастере:

```bash
# сначала посмотреть, что будет сделано
asterisk-cluster-sync

# применить
asterisk-cluster-sync --apply

# разложить диалплан по площадкам
asterisk-cluster-push-dialplan --nodes=site-1=10.10.10.12
```

Проверка на площадке:

```bash
asterisk -rx "pjsip show endpoints"      # должны появиться те же номера
```

> `asterisk-cluster-sync` нужно запускать после **каждого** Apply Config.
> Как повесить это на хук FreePBX — в [05-operations.md](05-operations.md).

## 8. Телефон

Через провижининг (правильный путь):

```bash
phonectl add 00:15:65:aa:bb:cc 564 --vendor=yealink \
    --primary=10.10.10.12 --backup=10.10.10.11 --home=site-1 --label="Тест"
phonectl arm 001565aabbcc --minutes=30
phonectl url 001565aabbcc            # покажет URL с токеном
```

URL пропишите телефону вручную или раздайте через DHCP option 66. Телефон
получит и primary, и backup сервер сразу — failover настроится сам.

Для быстрой проверки без железа подойдёт софтфон (Zoiper, MicroSIP) с
ручным вводом двух серверов.

## 9. Приёмка

Прогоняйте по порядку, каждый пункт — отдельная проверка.

### База

- [ ] `wsrep_cluster_size` одинаков на обоих узлах (2, или 3 с арбитром)
- [ ] `wsrep_local_state_comment` = `Synced` на обоих
- [ ] `asterisk-cluster-health` на обоих узлах завершается без замечаний

### Конфигурация

- [ ] Номер, созданный в FreePBX, после `asterisk-cluster-sync --apply` виден
      на площадке (`pjsip show endpoints`)
- [ ] Удалённый в FreePBX номер после синхронизации исчезает и на площадке
- [ ] Правка диалплана после `asterisk-cluster-push-dialplan` доезжает до
      площадки (`asterisk -rx "dialplan show from-site"`)

### Звонки

- [ ] Телефон регистрируется на площадке: `pjsip show contacts` на site-1
- [ ] В общей БД видно, где он зарегистрирован:
      `SELECT endpoint, reg_server FROM ps_contacts;` — колонка `reg_server`
      **не должна быть пустой**
- [ ] Звонок между двумя телефонами на одной площадке проходит
- [ ] Звонок между телефоном на площадке и телефоном на мастере проходит
      **в обе стороны** — это проверка межузловых транков
- [ ] Набор `*777` называет имя узла, который обслуживает вызов

### Failover

- [ ] `systemctl stop asterisk` на site-1 → телефон перерегистрируется на
      мастер в течение 10–60 с (`pjsip show contacts` на мастере)
- [ ] В это время звонки на него проходят через мастер
- [ ] `systemctl start asterisk` на site-1 → телефон возвращается на primary
- [ ] `systemctl stop mariadb` на site-1 → Asterisk площадки теряет realtime;
      после старта БД номера возвращаются без перезапуска Asterisk

### Провижининг

- [ ] Телефон с чистой прошивкой получает рабочий конфиг по MAC
- [ ] `phonectl log` показывает результат `ok`
- [ ] Запрос **без токена** отвергается (403), в журнале `denied_token`
- [ ] Запрос **с закрытым окном** отвергается, в журнале `window_closed`
- [ ] Запрос с адреса вне `--phone-cidr` отвергается: `denied_network`

Последние три пункта — не формальность. Именно они отличают провижининг от
раздачи SIP-паролей всем желающим.

## 10. Что дальше

1. Погонять стенд неделю под нагрузкой, похожей на боевую.
2. Заменить самоподписанный сертификат провижининга, если ваши телефоны
   проверяют цепочку.
3. Убрать запасное правило ufw `allow 22/tcp` (оно открыто для всех адресов)
   и оставить только доступ из админской подсети.
4. Прочитать [04-production-rollout.md](04-production-rollout.md) — там про
   нумерацию, локальные транки и порядок ввода реальных площадок.
