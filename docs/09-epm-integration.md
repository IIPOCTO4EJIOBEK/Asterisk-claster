# Интеграция OSS Endpoint Manager

Провижининг остаётся на штатном OSS PBX End Point Manager 16 — он уже
обслуживает 284 телефона и переучивать людей ради собственного сервера
незачем. Здесь описано, как научить его выдавать телефонам **резервный
регистратор**, без чего failover не работает.

## Что EPM делает и чего не делает

Разобрано по коду модуля (`ossepm16.tgz`, версия 16.0.0).

**Делает:**

- хранит телефоны в `endpointman_mac_list`, их линии — в `endpointman_line_list`;
- берёт пароль SIP прямо из настроек добавочного FreePBX;
- собирает конфиг из шаблона модели (`_ep_phone_modules/endpoint/<бренд>/<модель>/`);
- умеет отдавать конфиги файлами в каталог (`server_type = file`, как у вас)
  или по HTTP через `provisioning/p.php` (`server_type = http`);
- поддерживает переопределение настроек **на устройство** —
  поле `endpointman_mac_list.global_settings_override`.

**Не делает:** резервного SIP-сервера. Во всей модели данных есть ровно один
адрес — глобальный `srvip`, и он один на всю установку:

```
endpointman_global_vars: srvip = 10.1.10.111
```

Подстановка в шаблон идёт из `base.php`:

```php
'{$srvip}'        => $this->settings['line'][0]['server_host'],
'{$server.ip.1}'  => $this->settings['line'][0]['server_host'],
```

Второго адреса в этой карте нет. Значит, резервный сервер нужно добавлять
самим — и есть ровно два места, куда это встроить штатно.

## Как устроен failover в кластере

Разделение простое, и оно ложится на возможности EPM без правки его кода:

| Что | Значение | Где задаётся |
|---|---|---|
| Основной регистратор | Asterisk своей площадки — **у каждой свой** | переопределение на устройство |
| Резервный регистратор | мастер — **один и тот же для всех** | шаблон модели |

Резервный одинаков для всех телефонов, поэтому его можно вписать в шаблон
литералом. Основной у каждой площадки свой — его расставляет
`scripts/epm-set-site.py`.

## Шаг 1. Резервный сервер в шаблоне

EPM позволяет редактировать шаблоны моделей: **Endpoint Manager → Templates**,
либо править файлы в
`/var/www/html/admin/modules/_ep_phone_modules/endpoint/<бренд>/<модель>/`.

> Правьте через интерфейс либо делайте копию шаблона. Файлы в
> `_ep_phone_modules/` перезаписываются при обновлении модуля из репозитория
> вендора.

### Yealink

В шаблон линии добавьте блок резерва. `{$server.ip.1}` останется основным
адресом и будет разным у каждой площадки, `10.1.10.111` — адрес мастера:

```
account.1.sip_server.1.address = {$server.ip.1}
account.1.sip_server.1.port = {$server.port.1}
account.1.sip_server.1.expires = 600
account.1.sip_server.1.retry_counts = 3

# Резервный регистратор — мастер кластера
account.1.sip_server.2.address = 10.1.10.111
account.1.sip_server.2.port = 5060
account.1.sip_server.2.expires = 600
account.1.sip_server.2.retry_counts = 3

# Без этих трёх строк телефон резерв не включит и обратно не вернётся
account.1.fallback.redundancy_type = 1
account.1.fallback.timeout = 60
account.1.failback_mode = 1
account.1.retry_interval = 10
```

Одного `sip_server.2.address` недостаточно — это самая частая ошибка.
Без `fallback.redundancy_type` телефон считает второй сервер просто вторым
аккаунтом, а без `failback_mode` остаётся на мастере до перезагрузки, и
площадка стоит без нагрузки при живом локальном сервере.

### Grandstream

```
P47  = {$server.ip.1}     # SIP Server
P2312 = 10.1.10.111       # Backup Outbound Proxy
P2333 = 1                 # возврат на основной
P2334 = 60                # интервал возврата, сек
```

### Проверка

Пересоберите конфиги (**Rebuild Configs** в EPM или `fwconsole endpoint
rebuildall`) и посмотрите готовый файл телефона в каталоге провижининга:

```bash
grep -A2 'sip_server' /tftpboot/<MAC>.cfg
```

## Шаг 2. Основной сервер — по площадкам

Опишите площадки и диапазоны номеров:

```
# sites.conf — имя:IP Asterisk:диапазоны добавочных
rostov:10.1.10.111:10800-10999,1000-1999
voronezh:10.4.3.6:2000-2999
slavyansk:10.5.1.4:3000-3999
```

Затем:

```bash
epm-set-site --sites sites.conf              # план, ничего не меняет
epm-set-site --sites sites.conf --apply --rebuild
```

Скрипт заполняет `global_settings_override` у каждого телефона —
PHP-сериализованный массив с ключом `srvip`, ровно того же формата, что
пишет интерфейс модуля, когда вы правите настройки одного телефона руками.
Ничего нештатного он не делает: тот же механизм, только массово.

Телефоны без совпадения по диапазону остаются на глобальном `srvip` —
скрипт отдельно сообщает, сколько таких. Это признак, что план нумерации
шире, чем описан в `sites.conf`.

## Шаг 3. Раздача конфигов на площадках

У вас `server_type = file`: EPM пишет конфиги в каталог, телефоны забирают
их по TFTP/HTTP. Каталог живёт на мастере.

Телефон площадки ходит за конфигом на мастер — и это нормально: конфиг
нужен раз в сутки, а не на каждый вызов. Если мастер недоступен, телефон
работает на уже полученном конфиге, где прописаны оба сервера. Провижининг
не участвует в failover, поэтому дублировать его на площадки не требуется.

Если всё же хотите локальную раздачу — синхронизируйте каталог на площадки
и раздавайте оттуда:

```bash
rsync -az --delete /tftpboot/ root@10.4.3.6:/tftpboot/
```

и укажите в DHCP option 66 каждой площадки её локальный адрес.

## Порядок при вводе новой площадки

1. Развернуть узел: `clone-node.sh`.
2. Добавить его в `sites.conf`.
3. `epm-set-site --sites sites.conf --apply --rebuild`.
4. Перезагрузить телефоны площадки (или дождаться суточного цикла
   автопровижининга).

Пароли SIP при этом не меняются — телефон продолжает регистрироваться теми
же учётными данными, просто теперь на своей площадке.

## Что проверять после

```bash
# Где зарегистрированы телефоны
mysql asterisk -e "SELECT reg_server, COUNT(*) FROM ps_contacts GROUP BY reg_server;"
```

После расстановки площадок телефоны должны распределиться по узлам. Если
все по-прежнему на мастере — конфиги не пересобраны либо телефоны ещё не
перечитали их.

Проверка failover: остановите Asterisk на площадке и убедитесь, что её
телефоны появились на мастере в течение `retry_interval` × число попыток.

## Собственный сервер провижининга

В репозитории есть свой сервер (`provisioning/`) с шаблонами Yealink,
Fanvil и Grandstream и утилитой `phonectl`. Он **не нужен**, если вы
остаётесь на EPM, — это альтернатива для площадок, где EPM не ставится,
и справочный материал по правильному оформлению failover у разных вендоров.
Разворачивается отдельно (`install-provisioning.sh`) и с EPM не конфликтует,
поскольку слушает свой порт и свою таблицу.
