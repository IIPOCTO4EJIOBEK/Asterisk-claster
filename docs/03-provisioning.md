# Автопровижининг

Свой сервер провижининга: nginx + PHP, без платного FreePBX Endpoint Manager
и без облачных RPS вендоров. По MAC-адресу телефон получает конфиг, где уже
прописаны основной и резервный SIP-сервер — failover настраивается сам, при
первом включении.

## Модель угроз

Провижининг раздаёт **SIP-пароли**. Кто получил конфиг — тот может
регистрироваться как этот абонент и звонить за ваш счёт.

MAC-адрес секретом не является: он написан на корпусе телефона, виден в
ARP-таблице коммутатора и в DHCP-логах, а внутри вендорского OUI перебирается
за считаные минуты. Поэтому «отдавать конфиг всем, кто знает MAC» —
это отдавать учётки всей телефонии любому, кто дошёл до розетки.

Защита здесь состоит из четырёх независимых слоёв. Каждый можно обойти по
отдельности; смысл в том, что обходить нужно все сразу.

| Слой | Что делает | Настройка |
|---|---|---|
| 1. Сеть | принимаются запросы только из подсети телефонов | `allowed_cidrs` |
| 2. Токен | в URL обязателен HMAC-токен или общий секрет | `require_token` |
| 3. Окно | пароль отдаётся только когда админ открыл окно | `phonectl arm` |
| 4. Журнал | каждое обращение пишется в `provision_log` | всегда |

Плюс транспорт: только HTTPS, ограничение частоты запросов в nginx
(10/мин с адреса), заголовок `Cache-Control: no-store`.

### Про окно провижининга

Это главное отличие от «просто отдать по MAC». Обычный режим работы такой:

```bash
phonectl add 00:15:65:aa:bb:cc 564 --primary=10.4.3.6 --backup=10.10.10.11
phonectl arm 001565aabbcc --minutes=30     # открыли окно на время установки
# ... монтажник включает телефон, тот забирает конфиг ...
# через 30 минут окно закрывается само
```

Вне окна сервер отвечает `403` и пишет в журнал `window_closed`. Знание MAC
не даёт ничего.

Если телефон должен перечитывать конфиг по расписанию (например, чтобы
подхватывать смену адресов площадок), для него ставится `--always-allow`.
Это осознанное ослабление: такой телефон отдаст свой конфиг любому, кто
пройдёт слои 1 и 2. Ставьте точечно, а не всем подряд.

## Установка

Разворачивается автоматически на мастере в составе `install-master.sh`.
Отдельно:

```bash
./scripts/install-provisioning.sh \
  --db-name=asterisk --db-user=prov_ro --db-pass='...' \
  --hmac-secret='...' --port=8443 \
  --phone-cidr=10.4.0.0/16 --node-ip=10.10.10.11
```

Что получится:

```
/var/www/provisioning/
    public/index.php        <- единственное, что видно снаружи
    src/Provisioner.php     <- вне web root
    templates/*.php         <- вне web root
/etc/asterisk-cluster/provisioning.php   <- конфиг с паролем БД, 0640
/usr/local/bin/phonectl                  <- управление
```

Веб-скрипт ходит в базу под отдельным пользователем `prov_ro`, у которого
есть только `SELECT` на `phone_provision`, `ps_auths`, `ps_endpoints` и
запись в `provision_log`. Под `asterisk_rt`, у которого есть запись во всю
схему, провижининг не работает намеренно.

## URL для телефона

Форма имени файла у вендоров разная — сервер принимает все три варианта:

| Вендор | Что запрашивает прошивка | URL провижининга |
|---|---|---|
| Yealink | `<MAC>.cfg` | `https://<ip>:8443/prov/$MAC.cfg?t=<токен>` |
| Fanvil | `<mac>.cfg` | `https://<ip>:8443/prov/$mac.cfg?t=<токен>` |
| Grandstream | `cfg<MAC>.xml` | `https://<ip>:8443/prov/` |

Токен бывает двух видов:

- **персональный** — HMAC от MAC, разный для каждого телефона.
  Показывает `phonectl url <mac>`. Подходит, когда URL вводится вручную.
- **общий** — один на всех, задаётся `--static-token=` при установке.
  Нужен для DHCP option 66, где URL одинаков для всей сети.

Общий токен слабее: он виден любому, кто снимет DHCP-ответ в этой сети.
Он и не задуман как единственная защита — за ним стоят слои 1, 3 и 4.

### DHCP option 66

```
option tftp-server-name "https://10.10.10.11:8443/prov/$MAC.cfg?t=ОБЩИЙ_ТОКЕН";
```

Телефон подставит свой MAC вместо `$MAC` сам.

## Управление телефонами

```bash
# Завести телефон
phonectl add 00:15:65:aa:bb:cc 564 \
    --vendor=yealink --model=T31G \
    --primary=10.4.3.6 --backup=10.10.10.11 \
    --home=voronezh --label="Приёмная" --timezone=+3

# Открыть окно и сразу получить URL
phonectl arm 001565aabbcc --minutes=30

# Список телефонов площадки
phonectl list --node=voronezh

# Кто и когда забирал конфиги
phonectl log --limit=50
phonectl log --mac=001565aabbcc

# Закрыть окно досрочно / удалить
phonectl close 001565aabbcc
phonectl rm 001565aabbcc
```

Колонка `Окно` в `phonectl list` показывает, кто сейчас может забрать
конфиг. Полезно просматривать периодически: телефон, у которого окно
открыто месяцами, — это забытая дверь.

## Откуда берутся учётные данные

Логин и пароль читаются из realtime-таблицы `ps_auths` — той же, из которой
их берёт Asterisk. Конфиг телефона всегда соответствует текущему состоянию
системы, отдельного хранилища паролей нет.

Берутся **оба** поля, `username` и `password`. В FreePBX auth username не
обязан совпадать с номером добавочного, и подстановка номера вместо
username даёт телефон, который не может зарегистрироваться.

Если у добавочного пустой пароль (например, `auth_type` не `userpass`),
сервер отвечает `409` и пишет в журнал `empty_password`. Выдать телефону
пустой пароль было бы хуже, чем отказать: он бы бесконечно перерегистрировался.

## Интервал перерегистрации

По умолчанию `register_expires = 600` секунд, а не 60.

Причина — стоимость: каждая перерегистрация телефона это `UPDATE` в
`ps_contacts`, а таблица синхронно реплицируется на все площадки. На 1200
абонентах при 60-секундном интервале получается около 20 транзакций в
секунду **на весь кластер**, круглосуточно, ради данных, которые почти
никогда не меняются.

При этом на скорость failover этот интервал почти не влияет: телефон
переключается на резервный сервер по неответу, а не по истечении регистрации.
Управляет этим `retry_interval` (10 с) и число попыток.

Менять так:

```bash
./scripts/install-provisioning.sh ... --expires=600
```

## Добавление вендора

Шаблоны — обычные PHP-файлы в `provisioning/templates/`. Доступные
переменные: `$mac $extension $label $authUser $secret $primary $backup
$sipPort $expires $timezone`.

1. Создайте `provisioning/templates/<вендор>.cfg.php`.
2. Добавьте вендора в карту `$map` в `Provisioner::render()`.
3. Экранируйте подстановки: значения приходят из БД, а перевод строки внутри
   значения ломает формат конфига (в готовых шаблонах для этого есть `$esc`).

Обязательно проверьте, как именно у вендора включается резервный сервер.
Одного «второго адреса» обычно мало: у Yealink нужен
`fallback.redundancy_type`, у Fanvil — `Enable Failback`, у Grandstream —
Backup Outbound Proxy. Без этого телефон либо не переключится, либо
переключится и не вернётся.

## Проверка

```bash
# Отказ без токена — ожидаем 403
curl -sk -o /dev/null -w '%{http_code}\n' \
  "https://10.10.10.11:8443/prov/001565aabbcc.cfg"

# С токеном и открытым окном — ожидаем 200 и конфиг
phonectl arm 001565aabbcc --minutes=5
curl -sk "https://10.10.10.11:8443/prov/001565aabbcc.cfg?t=<токен>"

# Что записалось в журнал
phonectl log --limit=5
```
