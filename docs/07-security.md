# Безопасность

Телефонная система — это система, через которую можно тратить деньги.
Скомпрометированная учётка SIP превращается в исходящие звонки на платные
международные направления, и счёт приходит владельцу.

## Что защищаем

| Актив | Где лежит | Чем грозит утечка |
|---|---|---|
| Пароли SIP-абонентов | `ps_auths` | звонки за ваш счёт, прослушивание |
| Учётки транков провайдеров | `ps_registrations`, локальные конфиги | то же, в большем масштабе |
| Пароли БД | `/etc/asterisk-cluster/cluster.env` | полный доступ ко всему |
| Доступ к FreePBX GUI | мастер, порт 80/443 | полный контроль над телефонией |
| Записи разговоров, CDR | мастер | утечка коммерческой информации |

## Секреты

Скрипты **не содержат рабочих паролей по умолчанию**. Если пароль не передан
параметром, он генерируется случайным (32 символа) и печатается один раз в
конце установки.

Это сделано намеренно: значения вида `ChangeMe_SST_Pass`, которые «работают
из коробки», доезжают до продакшена практически всегда.

Где что лежит:

```
/etc/asterisk-cluster/cluster.env       0600 root:root    пароли БД
/etc/asterisk-cluster/provisioning.php  0640 root:www-data пароль prov_ro, HMAC
/etc/asterisk/res_odbc.conf             0640 asterisk      пароль realtime
/etc/mysql/mariadb.conf.d/60-galera.cnf 0640 root          пароль SST
```

`config/cluster.env` в репозитории — в `.gitignore`. Проверка на попадание
секретов в индекс встроена в `scripts/lint.sh` и в CI.

Для продакшена держите секреты в менеджере (ansible-vault, HashiCorp Vault)
и передавайте параметрами при установке, а не редактируя файлы на узлах.

## Сетевой периметр

Firewall расставляется установщиками. Итоговая картина:

| Порт | Откуда | Зачем |
|---|---|---|
| 22/tcp | `--admin-cidr` | SSH |
| 3306, 4444, 4567, 4568/tcp | `--cluster-cidr` | Galera |
| 5060/udp, 5061/tcp | везде | SIP от телефонов |
| 10000–20000/udp | везде | RTP |
| 80, 443/tcp | `--admin-cidr` | FreePBX GUI, только мастер |
| 8443/tcp | `--phone-cidr` | провижининг, только мастер |

> **Обязательно после установки.** Установщики добавляют запасное правило
> `ufw allow 22/tcp` для всех адресов, чтобы не отрезать администратора от
> сервера в процессе. Уберите его, когда убедитесь, что доступ из админской
> подсети работает:
> ```bash
> ufw status numbered
> ufw delete <номер правила 'ssh fallback'>
> ```

БД слушает `0.0.0.0`, доступ ограничивается firewall'ом. Это осознанный
выбор: Galera требует связности между узлами по нескольким портам, и
управлять этим одним `bind-address` не выйдет. Если межплощадочная сеть не
доверенная — заворачивайте Galera в VPN, а не открывайте порты в интернет.

**Порт 5060 открыт всем** — иначе телефоны не зарегистрируются. Это главная
поверхность атаки: сканеры SIP находят открытый порт за часы. Обязательные
меры:

```bash
# fail2ban с готовым фильтром для Asterisk
apt install fail2ban
cat >/etc/fail2ban/jail.d/asterisk.conf <<'EOF'
[asterisk]
enabled  = true
port     = 5060,5061
filter   = asterisk
logpath  = /var/log/asterisk/security
maxretry = 5
bantime  = 3600
findtime = 600
EOF
systemctl restart fail2ban
```

В Asterisk включите журнал безопасности (`logger.conf`: `security => security`)
— без него fail2ban нечего читать.

Дополнительно в `pjsip.conf` уже задано
`endpoint_identifier_order=username,auth_username,ip,anonymous`, а не с
`anonymous` в начале: анонимные вызовы не должны опознаваться раньше
легитимных.

## Провижининг

Подробная модель угроз — в [03-provisioning.md](03-provisioning.md).
Ключевое:

- MAC-адрес **не является секретом**, поэтому одного его недостаточно;
- пароль отдаётся только внутри открытого окна (`phonectl arm`);
- только HTTPS, только из подсети телефонов, с ограничением частоты;
- отдельный пользователь БД `prov_ro` с правом чтения нужных таблиц;
- каждое обращение — в `provision_log`.

Самоподписанный сертификат по умолчанию годится для телефонов, которые не
проверяют цепочку (большинство). Если ваши проверяют — положите нормальный:

```bash
# сертификат от вашего CA или Let's Encrypt
cp fullchain.pem /etc/asterisk-cluster/provisioning.crt
cp privkey.pem   /etc/asterisk-cluster/provisioning.key
chown root:www-data /etc/asterisk-cluster/provisioning.key
chmod 0640 /etc/asterisk-cluster/provisioning.key
systemctl reload nginx
```

## Межузловые транки

По умолчанию транки между площадками аутентифицируются **по IP-адресу**
(`type=identify`). Это корректно, только если межплощадочная сеть
доверенная — site-to-site VPN или выделенный L2.

Если трафик идёт через недоверенную сеть, включите пароль:

```bash
./scripts/make-node-trunks.sh \
  --peers-map=rostov=10.10.10.11,voronezh=10.4.3.6 \
  --trunk-pass='<общий секрет, одинаковый на всех узлах>'
```

Но пароль в SIP по UDP передаётся в открытом виде дайджестом — от
пассивного слушателя он не спасает, только от подстановки. Полноценное
решение для недоверенной сети — VPN между площадками либо TLS+SRTP.

## Разграничение доступа

- **FreePBX GUI** — отдельные учётки администраторов, не общий `admin`.
  Двухфакторная аутентификация в модуле User Management.
- **SSH** — только по ключам, `PasswordAuthentication no`.
- **root в БД** — только через unix-сокет, без сетевого доступа.
- **`asterisk_rt`** — права только на нужную схему, без `GRANT` и без
  доступа к `mysql.*`.

## Проверка перед вводом в эксплуатацию

```bash
# Пароли по умолчанию нигде не остались
./scripts/lint.sh

# Что реально слушает наружу
ss -tulnp | grep -vE '127.0.0.1|::1'

# Права на файлы с секретами
ls -l /etc/asterisk-cluster/
stat -c '%a %U:%G %n' /etc/asterisk/res_odbc.conf

# Правила firewall
ufw status verbose

# Нет ли добавочных со слабыми паролями
mysql asterisk -e "SELECT id, LENGTH(password) len FROM ps_auths
  WHERE LENGTH(password) < 12 ORDER BY len;"

# Аномалии провижининга за неделю
mysql asterisk -e "SELECT src_ip, result, COUNT(*) c FROM provision_log
  WHERE ts > NOW() - INTERVAL 7 DAY GROUP BY src_ip, result
  HAVING c > 10 ORDER BY c DESC;"
```

Последний запрос — про попытки перебора. Много `unknown_mac` с одного
адреса означает, что кто-то перебирает MAC-адреса; много `denied_token` —
что кто-то нашёл провижининг и пробует его открыть.

## Что осталось за рамками

Честный список того, чего этот репозиторий не делает:

- **Шифрование SIP/RTP (TLS + SRTP)** — порт 5061 открыт, но сертификаты и
  `transport-tls` не настраиваются. Для внутренней сети обычно не нужно, для
  абонентов через интернет — обязательно.
- **Шифрование трафика Galera** — репликация идёт открытым текстом.
  Полагается на доверенную сеть между площадками.
- **Ограничение направлений исходящих звонков** — защита от разорительного
  трафика при компрометации учётки настраивается в FreePBX (Outbound Routes,
  лимиты по стоимости) и остаётся на вас.
- **Централизованный сбор логов** — журналы остаются на узлах.
