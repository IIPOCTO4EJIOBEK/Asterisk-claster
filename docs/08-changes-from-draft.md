# Что изменено относительно первого черновика

Репозиторий вырос из трёх файлов черновика (`asterisk-test-lab-deploy.md`,
`clone-node.sh`, `provisioning-generate.php`). Здесь перечислено, что в них
не работало и как это решено — чтобы при сравнении с исходными файлами было
понятно, почему сделано иначе.

## Блокеры: стенд не проходил собственный чек-лист

### 1. Регистрации телефонов не были общими

**Было.** В `extconfig.conf` перечислены `ps_endpoints`, `ps_aors`,
`ps_auths`, `ps_registrations`.

**Проблема.** `ps_registrations` — это исходящие регистрации Asterisk на
транки провайдера, а не регистрации абонентов. Абоненты живут в
`ps_contacts`, которого в списке не было, поэтому Asterisk хранил их
локально в astdb. Узлы не видели регистраций друг друга — а на этом
держалась вся идея кластера.

**Стало.** `ps_contacts` в realtime плюс `ps_endpoint_id_ips`,
`ps_domain_aliases`. Добавлен `sorcery.conf`, без которого `res_pjsip` не
идёт в realtime даже при заполненном `extconfig.conf` — в черновике этого
файла не было вовсе.

### 2. FreePBX не заполняет таблицы `ps_*`

**Было.** «Через FreePBX GUI создайте номера, Apply Config — это заполнит
`ps_endpoints`, `ps_aors`, `ps_auths` в общей БД».

**Проблема.** FreePBX хранит добавочные в своих таблицах и по Apply Config
рендерит статические файлы `/etc/asterisk/pjsip.*.conf`. Таблицы `ps_*`
остаются пустыми, и площадки не видят ни одного абонента. Это делало схему
неработоспособной целиком.

**Стало.** `scripts/sync-config.py` читает то, что FreePBX отрендерил, и
переносит в realtime-таблицы. Набор колонок берётся из `information_schema`,
поэтому скрипт переживает смену версии Asterisk. Диалплан, который в
realtime загонять бессмысленно, синхронизируется отдельно —
`scripts/push-dialplan.sh`.

### 3. Не было межузловой маршрутизации

**Было.** Пункт чек-листа «Звонок между номером на master и номером на slave
проходит».

**Проблема.** Механизма для этого в черновике не существовало: ни транков
между узлами, ни способа узнать, где зарегистрирован абонент. Пункт был
невыполним.

**Стало.** `systemname` на каждом узле → `ps_contacts.reg_server` →
`func_odbc.conf` (`ODBC_CONTACT_NODE`) → диалплан ведёт вызов на нужную
площадку через транк `node-<имя>`, который генерирует
`scripts/make-node-trunks.sh`. Для мастера под FreePBX — хук в
`[from-internal-custom]`, возвращающий управление FreePBX, если абонент
местный.

### 4. Разные версии Asterisk на узлах

**Было.** Мастер: FreePBX-инсталлятор. Площадка: `apt install asterisk`.

**Проблема.** В стоке Debian 11 это Asterisk 16, тогда как FreePBX ставит
18/21. Схема `ps_*` между мажорными версиями отличается набором колонок.

**Стало.** `clone-node.sh` подключает тот же репозиторий Sangoma и
отказывается продолжать при несовпадении с `--asterisk-major`.

### 5. Инсталлятор FreePBX ломал уже собранный кластер

**Было.** Сначала Galera, потом FreePBX.

**Проблема.** Инсталлятор разворачивает и настраивает собственную MariaDB,
переписывая конфигурацию кластера. Плюс `sng_freepbx_debian_install.sh`
рассчитан на Debian 12 и ставит фиксированную связку FreePBX 17 + Asterisk 21
— обещанного «интерактивно выбрать Asterisk 18, FreePBX 16» у него нет.

**Стало.** Порядок перевёрнут: FreePBX со своей локальной БД, затем эта БД
переводится в кластерный режим. Перед включением репликации выполняется
конвертация MyISAM-таблиц FreePBX в InnoDB — Galera реплицирует только
InnoDB, иначе узлы молча расходятся по данным.

### 6. `ufw enable` отрезал администратора

**Было.** Правила для Galera, SIP, RTP — и `ufw enable`. Порт 22 не открыт.

**Стало.** SSH разрешается первым правилом, до включения firewall. Плюс
запасное правило на все адреса, которое документация просит сузить после
установки.

### 7. Арбитр на мастере не давал кворума

**Было.** «`garbd` можно запустить прямо на test-master».

**Проблема.** Падение мастера уносит и узел, и его арбитра — оставшийся узел
всё равно оказывается 1 из 3. Арбитр помогает, только если умирает
независимо от узлов БД.

**Стало.** `install-garbd.sh` предупреждает при запуске на узле БД и
объясняет, почему нужен отдельный хост. Заодно исправлено имя службы:
в пакетах MariaDB это `garb`, а не `garbd`.

## Безопасность

### 8. Провижининг раздавал SIP-пароли всем

**Было.** HTTP на 8080, без аутентификации: кто знает MAC — тот получает
конфиг с паролем в открытом виде. MAC написан на корпусе телефона.

**Стало.** Четыре независимых слоя: ограничение по подсети, токен в URL,
окно провижининга, открываемое администратором на время установки телефона,
и журнал всех обращений. Транспорт — только HTTPS с ограничением частоты
запросов. Ответ при отказе больше не содержит подсказок о структуре БД
(черновик в 404 выдавал готовый `INSERT` со схемой таблицы).

### 9. Веб-скрипт ходил в БД под привилегированным пользователем

**Было.** `asterisk_rt` — тот же, у кого `INSERT/UPDATE/DELETE` на всю схему.

**Стало.** Отдельный `prov_ro`: `SELECT` на три таблицы, `INSERT` в журнал.

### 10. Рабочие пароли по умолчанию

**Было.** `ChangeMe_SST_Pass` и `ChangeMe_RT_Pass` в гайде, в скрипте как
значения по умолчанию и в PHP.

**Стало.** Обязательные параметры без дефолтов; если не переданы —
генерируются случайные и печатаются один раз. Проверка на пароли по
умолчанию встроена в `lint.sh` и CI.

## Ошибки, ломавшие установку на первом же запуске

| Черновик | Проблема | Решение |
|---|---|---|
| `Driver = MariaDB` в `odbc.ini` | пакет регистрирует драйвер как `MariaDB Unicode` | имя берётся из `odbcinst -q -d` |
| `apt install asterisk-odbc` | такого пакета в Debian нет, `res_odbc` в `asterisk-modules`; с `set -e` роняло скрипт | `first_available_pkg` с внятной ошибкой |
| `fastcgi_pass /run/php/php-fpm.sock` | реальное имя `php8.2-fpm.sock` → 502 | сокет ищется в `/run/php` |
| `auth_name = extension` | в FreePBX `ps_auths.username` не обязан совпадать с номером | берутся оба поля |
| `mysql -h <slave> -u root -p` | root доступен только через unix-сокет | проверка убрана |
| `endpoint_identifier_order=auth_username,ip,anonymous` | без `username` обычные телефоны не опознаются | `username,auth_username,ip,anonymous` |
| `systemctl enable --now garbd` | служба называется `garb` | ищется среди обоих имён |
| URL с `$mac` | Yealink подставляет `$MAC`; Grandstream просит `cfg<MAC>.xml` | приняты все три формы |

## `clone-node.sh`

| Черновик | Стало |
|---|---|
| `--role` парсился, но не использовался: `--role=master` молча ставил secondary | роль обрабатывается либо отвергается с объяснением |
| назывался идемпотентным, но перезаписывал конфиги без бэкапа | бэкап каждого файла перед записью |
| `wsrep_cluster_address` = мастер + сам себя | обязательный полный список `--peers` с проверкой, что узел в нём есть |
| `sleep 5` и проверка `wsrep_cluster_size` | ожидание состояния `Synced` до 180 с с прогрессом |
| `[ "$CLUSTER_SIZE" -lt 2 ]` падало при пустом значении | `cluster_size()` всегда возвращает число |
| нет проверок root, ОС, валидности IP | все проверки есть, плюс отдельный `preflight.sh` |

## Что добавлено сверх черновика

- `preflight.sh` — проверка сервера до установки, включая замер RTT между
  площадками (Galera синхронна, и задержка входит в время транзакции).
- `healthcheck.sh` + systemd-таймер, метрики для Prometheus.
- `galera-recover.sh` — восстановление кворума, включая выбор узла с
  наибольшим `seqno` при полном погашении кластера.
- `sync-config.py`, `push-dialplan.sh` — то, чем конфигурация вообще
  доезжает до площадок.
- `make-node-trunks.sh` — межузловые транки.
- `phonectl` — управление телефонами и окнами провижининга.
- Шаблоны Fanvil и Grandstream в дополнение к Yealink, с корректным
  включением failover у каждого вендора.
- `lint.sh` и CI: синтаксис bash/PHP/Python, проверка на пароли по
  умолчанию, проверка, что каждая переменная шаблонов кем-то задаётся.
- Документация: архитектура, стенд, провижининг, ввод в эксплуатацию,
  эксплуатация, разбор неполадок, безопасность.

## Что осталось нерешённым

Честности ради — то, что в этом репозитории по-прежнему не сделано:

- **Мастер остаётся единственной точкой управления.** Звонки при его падении
  идут, но завести номер негде. Варианты усиления описаны, но не
  автоматизированы.
- **CDR в Galera.** Скрипты предупреждают и предлагают вынести
  `asteriskcdrdb` из репликации, но не делают этого автоматически.
- **TLS/SRTP для SIP** не настраивается.
- **Транки провайдеров** в лабораторной схеме живут на мастере; локальные
  транки на площадках описаны, но их конфигурация специфична для провайдера
  и оставлена на внедрение.
